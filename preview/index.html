Laboratory flow (implemented)

Patient → Encounter → Diagnostic Order → Item
  → Specimen (accession at RECEIVED) → Observation
  → Interpretation → Report · verify → finalize → amend
  worklists · QC holds gate finalization · priority ROUTINE/URGENT/EMERGENCY

HTTP → DTO mapping → application services → domain → PostgreSQL (RLS)
Observation ≠ Interpretation ≠ Report — distinct at the type level. FINALIZED versions are immutable; amendments are reason-bound, manager-tier, append-only. QC never rewrites patient results.

HTTP transport — /api/v1 (GET · POST)

POST/patients · /diagnostic-orders · /order-items/{id}/specimens · observations · interpretations
POST/diagnostic-orders/{id}/transitions · /specimens/{id}/transitions (accession)
POST/reports/{id}/finalize · /reports/{id}/amendments · /quality/records · /quality/holds/release
GET·POST/terminology · /charges · /devices/{id}/acquisitions · /documents · /inventory · /setup · /departments
GET/worklist · /worklists · /patient/reports · /patient/documents (ownership-scoped)
Ops/healthz (liveness) · /readyz (readiness) · /metrics (bounded counters)
Explicit verbs only — no generic PATCH/PUT state mutation. Statuses: 400 · 401 (+WWW-Authenticate) · 403 · 404 · 405 · 409 (incl. IDEMPOTENCY_CONFLICT) · 413 · 415 · 422 · 500 generic-only. Errors always use { error: { code, message, correlationId, details } }.
